# Agentic Coding Workflow (タスク依頼から完了までのフロー)

このスキルは、LLM（AIエージェント）がユーザーからタスクを受け取り、完了させるまでの「Agentic Coding」の標準プロセスを定義したものです。他のLLMエージェントもこのフローを参照し、統一された高品質なアウトプットを出力するために利用します。

## 1. コンテキストの理解と前提確認 (Analysis)

タスクを開始する前に、必ず以下のドキュメントを確認し、プロジェクトのスコープとアーキテクチャの方向性を理解してください。

- `AGENTS.md`: 基本姿勢、プロダクトスコープ、共通実装ルール
- `docs/elevator_pitch.md` & `docs/user_story_mvp.md`: MVPのスコープとユーザーへの提供価値
- 修正対象のコードや既存の設計ドキュメント（必要に応じて周辺ファイルも確認）

## 2. 計画の立案と合意形成 (Planning)

いきなりファイルを修正するのではなく、まずは「どのように実装・修正するか」の案（ドラフト）を作成し、ユーザーに提示してください。

- **ドラフトの提示**: ユーザーにドラフトを見せ、フィードバック（「過度な強調表示や絵文字は避ける」「バージョンの表記は消す」など）を受けた場合は、柔軟に修正案を再提示します。
- **論理的な説明**: アーキテクチャの根幹に関わる判断や技術選定を行う際は、論理的な背景（なぜその技術がこのプロジェクトに最適か）を合わせて説明してください。
- **要件の確認**: 要件としてgithubのISSUEのURLを渡された時はghコマンドやgithubアプリを利用して、Github情報を取得してください。Githubに関してはブラウザ経由での情報の取得は禁止です。

## 3. 実装とドキュメントの同期 (Implementation & Refinement)

ユーザーから「OK」が出た段階で、実際の実装（またはファイルへの書き込み）を行います。

- **ブランチの切り替え**:　必ず`origin/main`ブランチからブランチを新規に作成し、参照元のISSUEに紐づけて実装を開始してください。そのブランチ名はissueタイトルの英語訳にしてください。
- **コーディング原則**: SOLID、YAGNI、DRY、KISSの原則を厳格に守り、現行MVPに必要な最小の実装に留めてください。
- **文章・コードのスタイル**: 過度な強調表示や絵文字は使用せず、客観的で簡潔なトーン（例: 技術記事のようなトーン）を維持してください。テストのタイトル等は必ず日本語で記述します。
- **ドキュメントの同期**: ソースコードを修正した際、その変更内容が `AGENTS.md` や `README.md` に影響を与える場合は、必ずドキュメント側も同時に更新してください。不要になった記述は積極的に削除し、ソースコードとドキュメントの差分が常にゼロになる状態を保ちます。

## 4. 検証とガードレールの確認 (Verification)

変更を加えた後は、プロジェクトのCI（ガードレール）の基準を満たしているか確認します。

- フォーマッタ（Prettier/ESLint等）が正しく適用されているか
- 型チェック（TypeScript）が通るか
- 単体テスト（Vitest等）の追加と実行が成功しているか
- 全体のビルドが成功するか

terraformの修正を行った時は、`terraform plan`を実行し変更差分を必ず確認してください

## 5. コミットとPull Requestの発行 (Commit & PR)

実装と検証が完了し、ユーザーから指示があった場合（またはファイルがステージングされた場合）、以下のフローでタスクを完了させます。

1. **コミット**: 変更内容を的確に表す「日本語のコミットメッセージ」を作成してコミットします（例: `feat: XXX機能の追加と関連ドキュメントの更新`、`docs: READMEのアーキテクチャ追記`）。
2. **Push**: リモートリポジトリへ現在の作業ブランチをPushします。
3. **PRの発行**: GitHub CLI (`gh pr create`) などを利用し、Pull Requestを自律的に発行します。PRの概要（Body）には、変更の意図とサマリーをマークダウン形式で簡潔に記載してください。
4. **CI**の結果確認: Github Actionの結果を確認し、CIが正常に終了することを確認してください。失敗した場合は修正し、完了するまで繰り返してください。

## 💡 ユーザーのよくある依頼プロンプト例

LLMを操作する際、ユーザーは以下のようなプロンプトでこのスキルをトリガーさせます。

- 「（要件）について実装案を箇条書きで記載して。記載前に案を見せて」
- 「過度な強調表示や絵文字はなくして、〇〇のようなパターンにして」
- 「ステージしています。日本語でコミットメッセージを書いてPushしてPRまで発行してください」
