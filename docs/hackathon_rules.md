# DevOps × AI Agent Hackathon

## ハッカソンの概要

DevOps × AI Agent Hackathon は、Google Cloud の AI 技術を活用し、AIエージェントの企画・開発・デプロイ・運用までを一貫して実践するハッカソンです。

単なるプロトタイピングではなく、実運用を見据えた DevOps プロセス全体をカバーすることが重視されています。

## テーマ・コンセプト

### 1. つくる

Google Cloud の AI を中核に、実務で役立つ独創的な AIエージェントを設計・実装する。

### 2. まわす

GitHub連携や CI/CD など DevOps のフローを構築し、AIを継続的に改善するサイクルを体験する。

### 3. とどける

Cloud Run などへのデプロイを通じて、スケーラブルな環境で本番品質のプロダクトをユーザーへ届ける。

## 技術要件

### 必須要件 1：Google Cloud アプリケーション実行プロダクトの利用

以下のいずれかから **1つ以上** を利用する必要があります。

- App Engine
- Google Compute Engine
- Google Kubernetes Engine（GKE）
- Cloud Run
- Cloud Functions
- Cloud TPU / GPU

### 必須要件 2：Google Cloud AI 技術の利用

以下のいずれかから **1つ以上** を利用する必要があります。

- Gemini Enterprise Agent Platform
- Gemini API
- Gemma
- Imagen
- Agent Builder
- ADK（Agents Development Kit）
- Speech-to-Text API
- Text-to-Speech API
- Vision AI API
- Natural Language AI API
- Translation AI API

### 任意で利用可能な技術

以下は任意で利用可能です。

- Flutter
- Firebase
- Veo
- Elasticsearch
- その他、任意の技術

## 審査基準

### 1. AIエージェントが価値の中心になっているか

評価観点：

- AIエージェントが作品の中心になっているか
- 自律的な判断・タスク実行があるか
- AIエージェントである必然性があるか

### 2. 設定した課題へのアプローチ力

評価観点：

- 課題設定が明確か
- 対象ユーザーが具体的か
- プロダクトとしてのストーリーに一貫性があるか
- 新規性があるか

### 3. ユーザビリティ

評価観点：

- 初見で使いやすいか
- 操作導線が自然か
- デザインが分かりやすいか

### 4. 実用性・体験価値の魅力

評価観点：

- 実際に使えるプロダクトになっているか
- 課題解決への効果があるか
- 体験価値に魅力があるか

### 5. 実装力

評価観点：

- 技術選定が妥当か
- Google Cloud / Google Cloud AI 技術を活用できているか
- 拡張性があるか
- 実運用を見据えた設計になっているか

## 提出物

作品提出時には、以下が必要です。

- GitHubリポジトリURL
  - 公開リポジトリであること
- デプロイ済みプロジェクトURL
  - 動作確認できる状態であること
- ProtoPedia に登録した作品URL

## ProtoPedia 登録時の主な必須項目

- 作品ステータス
- 作品タイトル
- 概要
- 動画URL
  - YouTube または Vimeo
- システム構成
  - システムアーキテクチャ図のアップロードが必須
- 開発素材
- タグ
  - `findy_hackathon` を必ず設定
- ストーリー
  - 解決したい課題と背景
  - 想定ユーザー
  - プロダクトの特徴
