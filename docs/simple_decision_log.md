# Simple Decision Log

各アーキテクチャの選定理由の簡易版です。（元々ProtoPediaの提出フォームに記載していたもの）

## 1. プロダクトアーキテクチャ

### フロントエンド: htmx + Express.js (+ EJS & Tailwind CSS)

htmxをExpress、EJSと組み合わせることで、ホットリロードの実現やExpressのエコシステムを利用した開発の効率化など、開発体験の向上につながっています。また、スタイリングには Tailwind CSS / Flowbite を採用し、モダンでレスポンシブなUIを素早く構築しています。

またSSR（サーバーサイドレンダリング）で画面を提供しているので、SPAの様な画面の表示に時間がかかる問題の解消や、変更があった画面のみを再配信する仕組み（HTML Fragment）を利用し、ユーザー体験の向上につながっています。

### バックエンド: Fastify + TypeScript

本番運用前のMVP開発のため、Cloud Runのコールドスタンバイを利用した料金を削減を行なっています。  
コールドスタンバイでは起動の際にオーバーヘッドが発生しますが、それを最小化するために、軽量で起動が高速なFastifyを選択しています。

また時間のかかるAI Agent処理（ペルソナシミュレーション）を、Cloud Tasks を用いて非同期ワーカーに逃がす設計にすることで、APIのタイムアウトを防ぎ、実運用にも耐えうるアーキテクチャとしています。

### MCPサーバー: ＠modelcontextprotocol/sdk + TypeScript

PersonaOps上で整理した要件を、エンジニアのAIコーディングに連携しやすくするために、MCPサーバーを構築しています。  
MCPサーバーにはビジネスロジックを持たせず、バックエンドAPIの呼び出しと、レスポンスのLLM向け整形に責務を限定しました。

ビジネスロジックをバックエンドへ集約し、フロントエンドとMCPサーバーが同じAPIを利用する構成にすることで、仕様の重複や実装差異を防ぎ、保守性と開発効率を高めています。

フロントエンド、バックエンドなどで明確に機能の責務分解を行うことで、コードが複雑になる状況を解消しています。

- フロントエンド: 画面の描画（EJS + Tailwind CSSによるHTML生成）と、htmxを利用したインタラクティブなUI状態の制御に特化します。データストアへの永続化処理やAIエージェントの直接的な制御などのビジネスロジックは一切持たず、バックエンドAPIへの呼び出しのみを実行します。
- バックエンド (API): すべてのビジネスロジック、データ永続化（Firestore/Cloud Storage）、およびAIエージェント（ADK）の実行とCloud Tasksを用いた非同期制御を集約します。フロントエンドとMCPサーバーの両方から共通で呼び出せるAPIエンドポイントを提供します。
- MCPサーバー: 外部のAIエージェント（CursorやClineなど）がPersonaOps内のデータや機能を利用できるようにするためのブリッジ（ツール定義とインターフェース）に特化します。ビジネスロジックは持たず、バックエンドAPIの呼び出しと、結果をLLM向けに整形する責務のみを担います。

### TypeScript + Zodの利用（ADKとの組み合わせ）

TypeScriptを利用することで、言語レベルの型チェックでシステム全体の安全性を担保します。

また、本プロダクトでは `Zod` を各所のインターフェース定義に活用しています。
具体的には、ADK（Agent Development Kit）に Zod スキーマを渡すことで、AIペルソナからのシミュレーション評価結果（JSON構造）を厳格に制御し、パースエラーを防いでいます。
さらに、MCPサーバーのツール入力スキーマ（`inputSchema`）にも Zod を使用しており、Zodで記述した詳細なテキストメタデータ（`.describe()`）がそのままLLM向けの仕様解説ドキュメント（JSON Schema）に自動変換される環境を構築し、開発時の型安全とLLMへの協調動作を両立しています。
また、ADKの `runEphemeral` メソッドを利用することで、Cloud Run環境でも「リクエスト間でAIの記憶が混ざらない」完全に隔離された安全なエージェント実行を実現しています。

### コスト最適化: 完全サーバーレスアーキテクチャ

今回は常時稼働のサーバーやデータベースを持たない「完全サーバーレスアーキテクチャ」を採用しました。  
プロダクトは、Cloud Run、Cloud Tasks、Firestore Nativeなど、利用した分だけ課金されるマネージドサービスのみで実装しています。

それにより、LLMの費用を除くと1環境あたり1日200円程度で運用ができ、MVPフェーズにおける圧倒的なコスト削減を実現しています。

### セキュリティ: IAMを利用したインフラレベルでの「境界防御」の実現

バックエンドAPIはパブリックなインターネットからの未認証アクセスを一切許可せず、FrontendとMCP Serverのランタイムに付与された専用サービスアカウントだけに呼び出し権限（`roles/run.invoker`）を限定しています。

悪意のある攻撃者が「APIだけを直接叩いて、DBデータを一括削除する」ような不正リクエストを送信しても、IAM認証によって完全にブロックされます。

## 2. DevOpsと開発プロセス

AIコーディングを最大限に生かすDevOpsの仕組みとして、GitHub ActionsでのCIとCloud Buildを利用したCDを実装しています 。

フロントエンド、バックエンド、インフラなど全てで`AGENTS.md`を作成し設計思想を明文化したり、プロダクトのエレベーターピッチやユーザーストリーマップを文書化して`docs/`フォルダに格納しています。

### CI: ガードレールとしてのCI

本プロジェクトでは、AIが自律的にコードを書き、AIがPRを発行する開発スタイルを取り入れています。そのためCIは、「AIが生成したコードの品質を担保するガードレール」としての役割を持ちます。

フロント・バックエンド（API、MCP）・Terraformインフラの全てにおいて、以下の項目をCIで検証しています。

- フォーマッタが正しく適用されているか
- 型チェック
- 単体テストのパス
- ビルドの成功

結果として、軽量なタスクであればGitHub Issueを読み込ませるだけでAIが開発を完了し、PRの発行まで自律的に完了する状態になっています。

### CD: フィードバック反映の高速化

Pull Requestをmainブランチにマージすると、Cloud Build（`infra/gcp/cloudbuild.yaml`）がフロントエンド、API、MCPサーバー、インフラのビルドからTerraformによるデプロイまでをすべて自動実行します。

これにより、AIが開発した機能をチームメンバーが即座に検証環境で確認でき、チームの機能開発のフィードバックループを、高速に回すDevOpsが実現できています。
