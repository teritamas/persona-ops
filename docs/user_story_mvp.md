# PersonaOps ユーザーストーリーマップ

## ペルソナ

プロダクトマネージャーの様なユーザーインタビュをメインで行いながらプロダクト企画を考える人

## 全体フロー

1. システムリリース
2. 次どういう機能をリリースしよう
3. A機能をリリースしようかな
4. 要件整理
5. ユーザーインタビュー
6. 機能開発
7. リリース→2に戻る

### 1. システムリリース

#### 課題・不安

- リリースアナウンスが面倒
- マニュアルのメンテが大変

#### ユーザーストーリー / 解決アイデア

- PRを発行した時に下記の素材を自動で生成される様にしたい
  - リリースアナウンス
  - GIFや動画で動くチュートリアル
  - 操作マニュアル

### 2. 次にどういう機能をリリースするか決める

#### 課題・不安

- リリースした機能が本当に課題を解決するのか不安
- ユーザーにもっと寄り添いたいが、タスクが流れてきてしまう

#### ユーザーストーリー / 解決アイデア

- システム内でユーザーアンケート機能を設置したい
- ユーザーの声を集めて、状況判断に使いたい

### 3. どの機能をリリースするか判断する

#### 課題・不安

- 優先順位を決めるのが大変
- MVPを決めるのが難しく、肥大化してしまう

### 4. 機能の要件定義

#### 課題・不安

- ペルソナ定義が不安
- 既存仕様との整合性を合わせるのが難しい

#### ユーザーストーリー / 解決アイデア

- ペルソナを自動生成したい
- ユーザーリサーチの要素をもとに、ペルソナを自動アップデートしたい
- 過去の要件を考慮して要件を整理できるようにしたい

### 5. ユーザーインタビュー

#### 課題・不安

- ユーザーとの日程調整が大変
- ユーザーに対して複数回もお願いしづらく、準備の工数が大きい
- 人相手なので、失礼のないように気を遣う

#### ユーザーストーリー / 解決アイデア

- AIがペルソナになって、新機能について質問・検討できるようにしたい
-

### 6. ステークホルダーとの合意 / 機能開発前の認識合わせ

#### 課題・不安

- 合意できる資料を作るのが大変
- 関係者間で認識がズレやすい
- 前に言っていたことと違うことを言われる
- 本当に解決したいこととズレてしまう

#### ユーザーストーリー / 解決アイデア

- 共有用の資料やドキュメントを自動作成したい
- 以前の議論における理由や背景をエビデンスとして参照したい

### 7. 機能開発・リリース

#### 課題・不安

- 本当に解決したいこととズレてしまう
- 仮説の精度が低く、見えづらい
- 開発中に要件がズレないか不安

#### ユーザーストーリー / 解決アイデア

- 開発中に要件がズレていないか確認したい

## PH1 開発領域

PH1では「設計書やリポジトリの情報からペルソナを作成し、そのペルソナに対して新機能の価値が伝わっているか」を検証・証明する領域を対象とする。

具体的には全体のユーザーストリーのうち「4. 要件定義」「5. ユーザーインタビュー」「」を対象とする。

### 課題・不安

- 新機能がユーザーに伝わっているか検証するのが難しい
  - 本当は頻繁にユーザーインタビューを行いたいが、時間やリソースが取れない
  - ユーザーの真意をヒアリングするには関係構築が必要でありハードルが高い
  - 複数ユーザーの意見を集めるのが大変
- 伝わっていることを証明するのが難しい
  - どのユーザーの意見を参考にしたか不明確
  - 過去のユーザーインタビューを活かしづらい

### ユーザーストーリー / 解決アイデア

- ペルソナを自動生成したい
  - ユーザーリサーチの要素をもとに、ペルソナを自動アップデートしたい
  - 過去の要件から認識・整理できるようにしたい
  - ペルソナは1人だけでなくグループの様な感じで生成し、その中でペルソナの共通項目の範囲内で差分が出る様にしたい
- ペルソナに新機能を伝えて、ペルソナの反応をシミュレーションしたい
  - ペルソナの反応を一覧で見えてその機能をリリースするかどうかの判定をしたい
  - ペルソナに個別にチャットをしたり、一括でアンケートを取ったりして、フィードバックを貰いたい

### 機能要件

#### ペルソナを自動生成したい

ChatGPTやCodexの様なチャット形式でエージェントと対話し、ペルソナの定義を作成する。ペルソナの定義の際には下記の様な資料を利用するので、入力できる様にする

- URL: Githubやオンラインマニュアルのリンク
- ファイル: PDFやMarkdownなどのテキストファイル

1つの会話ごとにプロジェクトが作られて、そのプロジェクトの名でペルソナが作られる。シミュレーションの結果は過去の履歴まで遡れる様にする。

適応したシミュレーションを利用してペルソナがどんどん成長していく。

ペルソナの情報はオントロジーで表現する。ペルソナを作成する時に利用したファイルやURLはそれぞれがRAGに保存されてペルソナの情報に参照情報として紐づけられる

会話履歴も構造化され長期記憶として記録しておく。

つまりペルソナのオントロジーのオブジェクトは、アップロードしたファイルのRAGのインデックスと会話履歴から作られた構造化された要件をデータとして持つ。

#### ペルソナへのシミュレーション

追加する機能の要件もチャット形式でAIとディスカッションして作成する。追加機能の要件もオントロジーで保持し保存する。

プロジェクトごとに。要件を複数保存できる。ペルソナにシミュレーションした要件もオントロジーオブジェクトとして保存する。
